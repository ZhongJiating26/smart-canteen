# 前端原型功能与接口缺口清单

本文根据 `prototype/canteen-prototype/`、`A智能食堂系统需求规格说明书.md` 与当前后端 Controller 进行核对。正式前端保留需求要求的能力，不因后端接口暂缺而删除业务入口；原型中仅用于丰富展示、但需求未要求的能力不纳入首批实现。

## 1. 保留且已有接口

| 前端能力 | 需求依据 | 当前接口 |
| --- | --- | --- |
| 用户注册、密码/验证码登录、资料查看修改 | FR-001 ~ FR-004 | `/api/user/**` |
| 游客浏览当前可售菜单、菜品详情 | FR-006、FR-008 | `/api/menu/available`、`/api/menu/dishes/{id}` |
| 购物车、确认订单、支付、订单列表和详情 | FR-008 ~ FR-010 | `/api/order/**`；购物车为前端本地状态 |
| 取餐二维码和排队位置 | FR-011、FR-013 | `/api/pickup/qrcode/{orderId}`、`/api/pickup/my-position/{orderId}` |
| 商家订单处理、出餐、叫号、手工核销 | FR-009、FR-012、FR-013 | `/api/order/merchant/**`、`/api/pickup/call`、`/api/pickup/verify` |
| 商家窗口身份、菜品、菜单和库存预警 | FR-005 ~ FR-007 | `/api/menu/merchant/me`、`/api/menu/dishes/**`、`/api/menu/daily-menus/**`、`/api/menu/inventory/alerts` |
| 管理员用户、商家、业务配置 | FR-015、权限需求 | `/api/admin/users/**`、`/api/admin/merchants/**`、`/api/admin/*/config` |
| 大屏队列、叫号和断线恢复 | FR-014 | `/api/pickup/snapshot/{merchantId}`、`/ws/screen/{merchantId}` |

## 2. 需求要求保留，但需要补充或确认后端接口

| 能力 | 判断 | 所需后端补充 |
| --- | --- | --- |
| 用户端“叫号弹窗提醒” | FR-012 及优先级 `Should Have` 要求保留。现有订单状态仅返回 `status/pickupNo/hasQrcode`，无法区分首次进入 READY 与再次手动叫号。 | 建议新增 `GET /api/pickup/my-call-events?afterId=...`，或在 `GET /api/order/{id}/status` 返回 `called`、`lastCallEventId`、`lastCallTime`。 |
| 商家扫码核销 | FR-013、硬件接口与验收标准要求保留。后端核销接口已有，缺口只在浏览器扫码解析方案，不是业务接口。 | 无必需业务接口；前端使用 `BarcodeDetector/getUserMedia`，不支持设备保留手输取餐码。 |
| 菜品分类完整维护 | 需求声明分类应支持配置，详细设计与原型包含分类删除。当前仅提供列表和新增。 | 新增 `PUT /api/menu/categories/{categoryId}` 与 `DELETE /api/menu/categories/{categoryId}`（删除需校验关联菜品或转为停用）。 |
| 用户修改登录/支付密码 | FR-004 将密码修改信息列为个人资料输入，原型个人中心有设置入口；当前资料修改 DTO 不支持密码。 | 新增 `PUT /api/user/password`、`PUT /api/user/pay-password`，包含原凭证/验证码校验规则。 |

## 3. 原型有展示，但首批正式前端移除

| 原型功能 | 处理理由 |
| --- | --- |
| 管理端仪表盘统计卡片 | “订单统计、菜品销量统计”为 `Could Have`，且无聚合统计接口；不阻塞主流程。 |
| 商家“店铺信息”独立工作区 | 商家自助维护窗口资料未列入商家权限；窗口维护归管理员。 |
| 商家“历史订单”独立视图 | 主需求为订单处理；现有商家列表接口可在订单工作台提供状态筛选，不新增独立页面。 |

## 4. 需产品确认的非阻塞项

当前依据需求已可继续开发，无阻塞性判断项。
