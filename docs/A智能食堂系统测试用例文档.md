# A智能食堂系统测试用例文档

## 1. 引言

### 1.1 编写目的

本文档用于说明 A 智能食堂系统的测试范围、测试环境、测试数据、测试方法、测试用例和验收标准。本文档面向测试人员、开发人员、课程设计评审人员和后续维护人员，为系统功能测试、接口测试、业务流程测试、权限测试、异常测试、性能测试和验收测试提供依据。

通过本文档中的测试用例，应能够验证系统是否满足《A智能食堂系统需求规格说明书》《A智能食堂系统概要设计说明书》《A智能食堂系统架构设计文档》和《A智能食堂系统详细设计说明书》中规定的功能、接口、权限、业务规则和非功能要求。

### 1.2 测试依据

| 序号 | 文档或资料                      | 说明                                                         |
| ---- | ------------------------------- | ------------------------------------------------------------ |
| 1    | 《A智能食堂系统需求规格说明书》 | 功能需求、业务规则、权限需求、非功能需求和验收依据           |
| 2    | 《A智能食堂系统概要设计说明书》 | 系统模块划分、子系统关系、数据总体设计和接口概要             |
| 3    | 《A智能食堂系统架构设计文档》   | 微服务架构、技术选型、前后端通信、部署和组件设计             |
| 4    | 《A智能食堂系统详细设计说明书》 | 接口路径、请求参数、响应格式、错误码、状态机、核心业务逻辑和数据结构 |

### 1.3 测试范围

#### 1.3.1 本次测试包含的范围

本次测试覆盖以下内容：

1. 用户注册、登录、验证码登录、Token 刷新、登出、用户资料查询与修改。
2. 商家菜品分类、菜品管理、每日菜单配置、上下架和库存管理。
3. 用户浏览菜单、提交订单、创建待支付订单、库存预占、模拟支付。
4. 订单状态流转：待支付、已下单/待接单、制作中、待取餐、已取餐、已取消。
5. 用户取消订单、商家拒绝接单、支付超时自动取消、接单超时自动取消。
6. 取餐号生成、制作中队列、待取餐队列、用户排队位置查询。
7. 商家出餐自动叫号、手动叫号、大屏叫号提示。
8. 取餐二维码生成、取餐码展示、扫码核销、手动输入取餐码核销。
9. 管理员用户管理、商家管理、窗口管理、业务配置管理。
10. 网关统一鉴权、角色权限控制、数据归属校验、接口限流。
11. WebSocket 大屏实时推送、断线重连和快照恢复。
12. 订单、库存、队列、二维码等核心数据一致性测试。
13. 性能、安全性、可靠性、可用性、兼容性等非功能测试。

#### 1.3.2 本次测试不包含的范围

本次测试不包含以下内容：

1. 真实微信、支付宝、银行卡等第三方支付资金结算测试。
2. 真实短信网关验证码发送测试。
3. 食堂硬件设备底层驱动测试。
4. 原生 Android / iOS App 测试。
5. 复杂优惠券、会员积分、评价、营销等未纳入需求范围的功能测试。
6. 生产级容灾切换、异地多活和长期稳定性压测。

## 2. 测试概述

### 2.1 测试目标

1. 验证系统各功能模块是否满足需求规格说明书中的功能需求。
2. 验证用户、商家、管理员、大屏终端等不同角色的权限边界是否正确。
3. 验证订单、库存、队列、取餐号和取餐二维码等核心业务数据是否保持一致。
4. 验证创建订单时库存预占、取消或超时时库存恢复、核销后确认消费库存的业务规则是否正确。
5. 验证订单状态流转是否符合规定流程，系统是否拒绝非法状态变更。
6. 验证接口返回格式、错误码、鉴权逻辑、限流逻辑是否符合详细设计要求。
7. 验证大屏端队列刷新、叫号提示、断线重连和快照恢复是否正常。
8. 验证系统在并发下单、高频查询和异常场景下是否具备基本可靠性。

### 2.2 测试类型

| 测试类型     | 测试说明                                                     |
| ------------ | ------------------------------------------------------------ |
| 功能测试     | 验证注册、登录、菜品、菜单、库存、订单、队列、叫号、核销等功能是否正确 |
| 接口测试     | 验证 REST API 请求参数、响应格式、错误码、权限和异常返回     |
| 业务流程测试 | 验证从浏览菜单到下单、支付、接单、出餐、叫号、核销的完整流程 |
| 权限测试     | 验证游客、普通用户、商家、管理员、大屏终端的操作边界         |
| 异常测试     | 验证库存不足、重复提交、非法状态、二维码失效、超时取消等异常场景 |
| 并发测试     | 验证多人同时下单时库存预占和防超卖能力                       |
| 性能测试     | 验证接口响应时间、并发浏览、并发下单和大屏推送延迟           |
| 安全测试     | 验证鉴权、越权、Token 失效、验证码频率限制、SQL 注入、XSS 等安全点 |
| 可靠性测试   | 验证 Redis 缓存异常、WebSocket 断连、RocketMQ 重复消息、服务异常等恢复能力 |
| 兼容性测试   | 验证手机浏览器、平板浏览器、PC 浏览器和大屏分辨率适配情况    |

### 2.3 测试通过标准

| 测试项         | 通过标准                                                     |
| -------------- | ------------------------------------------------------------ |
| 功能测试       | 高优先级功能用例全部通过，中低优先级用例无严重缺陷           |
| 接口测试       | 接口请求、响应格式、错误码、鉴权结果与详细设计一致           |
| 业务流程测试   | 核心链路“下单—支付—接单—出餐—核销”完整通过                   |
| 权限测试       | 未授权、越权、跨商家访问均被正确拒绝                         |
| 数据一致性测试 | 订单、库存、队列、二维码状态在正常和异常场景下保持一致       |
| 性能测试       | 满足需求中普通接口、菜单查询、大屏推送、并发在线和并发下单指标 |
| 安全测试       | 不存在高危安全缺陷，敏感接口限流和鉴权有效                   |
| 可靠性测试     | 缓存异常、消息重复、WebSocket 断线等场景可恢复或可补偿       |

### 2.4 测试暂停与恢复标准

#### 2.4.1 测试暂停标准

出现以下情况时，可以暂停测试：

1. 测试环境不可用，如网关、数据库、Redis、Nacos 等基础组件无法启动。
2. 核心服务无法正常注册或接口大面积不可访问。
3. 数据库结构与详细设计严重不一致，导致大量用例无法执行。
4. 订单创建、登录鉴权等基础链路阻塞，影响后续大部分用例。
5. 发现严重数据破坏问题，例如库存大量错误扣减、订单状态不可恢复。

#### 2.4.2 测试恢复标准

满足以下条件后恢复测试：

1. 测试环境恢复正常，核心组件和业务服务均可访问。
2. 阻塞性缺陷已修复并通过冒烟测试。
3. 测试数据已重新初始化或修复。
4. 影响范围已确认，并记录暂停和恢复时间。

### 13.4 总体结论

在完成全部高优先级功能测试、核心业务流程测试、接口测试、权限测试和数据一致性测试后，如系统满足以下条件，可认为本轮测试通过：

1. 用户注册、登录、Token 鉴权、用户信息维护等基础功能正常。
2. 商家菜品、每日菜单、库存、上下架等管理功能正常。
3. 用户下单、库存预占、模拟支付、订单状态流转符合设计要求。
4. 用户取消、商家拒绝、支付超时、接单超时等异常流程能够正确恢复库存。
5. 商家接单、出餐、叫号、二维码生成和核销流程完整可用。
6. 制作中队列、待取餐队列、大屏展示和 WebSocket 重连恢复正常。
7. 游客、普通用户、商家、管理员、大屏终端的权限边界正确，不存在严重越权问题。
8. 并发下单场景下库存不会超卖，重复请求不会导致重复订单或重复库存变更。
9. 系统接口响应格式、错误码、状态码和异常提示基本符合详细设计。
10. 不存在阻塞验收的高严重程度缺陷。

若以上条件均满足，则本系统可进入课程设计验收或下一轮部署联调阶段。
